为什么两个线程并发调用 put() 时可能丢失 key？

假设两个不同的 key（17 和 22）都映射到桶 2，桶原来的头节点为 H，
并且这两个 key 都不在表中。可能发生如下交错执行：

1. 线程 A 查找桶 2，没有找到 key 17。
2. 线程 B 查找桶 2，没有找到 key 22。
3. A 读取 table[2]，得到 H，准备把它作为 insert() 的最后一个参数，
   随后暂停执行。
4. B 也读取到桶头 H，为 key 22 分配新节点 B，设置 B->next = H，
   然后执行 table[2] = B。
5. A 恢复执行，使用之前读到的 H，为 key 17 分配新节点 A，
   设置 A->next = H，然后执行 table[2] = A。

最终链表为 A -> H。节点 B 虽然仍在内存中，但已经无法从桶头找到，
因此 get(22) 会报告 key 缺失。原因是 A 对桶头的更新覆盖了 B 的更新。
单线程运行时，每次插入都会在下一次插入读取桶头之前完成，
所以不会出现这种交错执行。

用互斥锁保护同一个桶的整个查找和更新过程，可以避免这个竞争问题。
每个桶使用一把锁，既能保证同一个桶的操作互斥，又允许不同桶的操作并行。
